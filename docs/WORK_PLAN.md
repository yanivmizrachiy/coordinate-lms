## סדר העבודה עד 100%

### שלב A — לסגור את בסיס הריפו

1. להשאיר PR פעיל אחד בלבד: PR #7 / `agent/canonical-lms-unified`.
2. לסרוק ולהסיר כל כלל ישן/קוד ישן שסותר את `RULES.md`.
3. להסיר הנחות `77`, registration wall, durable guest, teacher judgment למשימות דטרמיניסטיות, ו־`לא נדרש במתוקשב`.
4. לוודא שמספר העמודים בכל runtime/report נגזר מהחוברת ולא מקבוע ישן.

**שער:** אין סתירות ידועות ומקור אמת אחד בלבד.

### שלב B — להשלים את כל 78 הדפים המתוקשבים

1. לעבור לפי דוח answer coverage, עמוד־עמוד.
2. לכל יעד שאינו בדיק אוטומטית, לקבוע אינטראקציה מתאימה לפי `RULES.md`.
3. משימת נקודה/שרטוט → לחיצה/מגע ישיר + predicate מתמטי.
4. הרבה תשובות נכונות → בדיקת התנאי המתמטי, לא sample answer.
5. „הסבר מדוע” → בדרך כלל 4 אפשרויות דידקטיות איכותיות עם מסיחים אמיתיים.
6. לא להשאיר משימה קנונית מוסתרת או לא מתוקשבת רק מפני שהבדיקה מורכבת.
7. לחדש את דוח הכיסוי אחרי כל מקבץ תיקונים.

**שער:** כל משימה קנונית קיבלה אינטראקציה מתאימה; אין פער דיגיטלי לא מוסבר.

### שלב C — הרשמה, ציונים, שמירה ודוחות

1. אורח פותר הכול, מקבל משוב וציון זמני, אך אינו נשמר.
2. הרשמה מחייבת: שם מלא, שם משתמש, אימייל, סיסמה, בית ספר, עיר וכיתה.
3. משתמש רשום: טיוטות, ניסיונות, ציונים, פעילות והתקדמות נשמרים.
4. דוחות מורה כוללים רק נרשמים וכל 78 העמודים.
5. תלמיד רואה רק את המידע שלו.

**שער:** בדיקות יחידה + Firestore emulator + סימולציית שני תלמידים עוברות. **עבר בקוד הנוכחי; נדרש אימות production.**

### שלב D — אבטחה ו־Firebase production

1. Firebase Authentication בלבד בייצור.
2. אין סיסמאות ב־Firestore/לוגים/דוחות/קוד.
3. להגדיר את כל סודות Firebase הנדרשים ב־GitHub/production.
4. לפרוס Firestore rules/indexes.
5. לוודא owner-only לתלמיד ו־admin-only לדשבורד כיתתי.
6. להריץ readiness אמיתי, לא static בלבד.

**שער:** Firebase readiness ללא חסמי production וכללי ההרשאה עברו בפועל.

### שלב E — גרפיקה וחוויית שימוש

1. בדיקת כל 78 הדפים בדסקטופ ובמובייל.
2. RTL, שרטוטים, לחצנים, zoom, טפסים, feedback, ציונים ומסגרת ההרשמה.
3. A4 נשאר נאמן להדפסה; שכבת LMS לא דולפת להדפסה.
4. תיקון overflow, חיתוכים, טקסט קטן, לחצנים לא נגישים או שרטוט לא לחיץ.
5. visual regression + accessibility + mobile interaction.

**שער:** Playwright/A4/mobile/visual עוברים ללא כשל.

### שלב F — קבלה ופרסום

1. בדיקה אמיתית בטלפון תלמיד: כניסה כאורח, פתרון, הרשמה, המשך פתרון ושמירה.
2. בדיקה נפרדת במחשב מורה: הופעת התלמיד והנתונים הנכונים בלבד.
3. לוודא ציון, ניסיונות, דוח, logout/login ושחזור התקדמות.
4. לסגור PRים ישנים רק לאחר שווידאנו שכל שינוי ייחודי נדרש נשמר ב־PR #7.
5. למזג ל־main.
6. לפרוס production.
7. לפתוח את הקישור החיצוני ולבצע smoke test אחרון.

**שער 100%:** קישור production עובד ומוכן לשליחה לאנשים חיצוניים.
